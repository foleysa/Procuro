# Diligence Pack section IDs

One horizontal template. Edition depth is an appendix, not a new pack
type each time.

Buyer-provided files under a Procuro MSA are in-bounds. **FSA client
files are not**, unless John greenlights a bridge.

## IDs (`DiligenceSectionId`)

| ID | Title | Scope |
|---|---|---|
| `diligence.exec_summary` | Executive summary | Horizontal |
| `diligence.spend_shape` | Spend, suppliers, contracts | Horizontal |
| `diligence.supplier_concentration` | Supplier concentration | Horizontal |
| `diligence.category_inflation` | Category inflation vs public index | Horizontal |
| `diligence.logistics_exposure` | Logistics exposure (core lens) | Horizontal |
| `diligence.judgment_opportunities` | Judgment opportunities (Decide candidates) | Horizontal |
| `diligence.risk_disruption` | Disruption and policy Observe | Horizontal |
| `diligence.edition_appendix` | Edition appendix (MRO / Food / later skins) | Edition |
| `diligence.methodology_and_limits` | Methodology and limits | Governance |
| `diligence.data_fences` | Data fences (Procuro LoE, no FSA client data) | Governance |

## How to use

1. Fill every **horizontal** section from public / licensed signal plus
   **this buyer’s** data.
2. Attach `diligence.edition_appendix` for the edition they bought
   (`mro` or `food` in Day 0–30). Same appendix slot for later skins.
3. `diligence.methodology_and_limits` states what is directional, what
   is unknown, and that peer language is withheld until a written N
   policy is met. No invented percentiles.
4. `diligence.data_fences` restates: Procuro ≠ FSA; no silent resale of
   raw identifiable spend; no FSA client data.

`judgment_opportunities` may list suggested Decide actions. It must not
claim realized savings without a Layer C Learn label of `saved` on
**that buyer’s** opportunities.
